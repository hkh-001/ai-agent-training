# Day 1 概念笔记与术语表

## 一页心智模型

```text
原始文本
  -> Tokenizer 将文本转换为 Token ID
  -> 模型根据全部可见上下文计算后续 Token 的概率
  -> 解码策略选择 Token
  -> 重复生成
  -> Token 被还原为可读文本
```

这张图有意省略神经网络内部数学细节，但保留了今天最重要的事实：模型输入输出的基本单位是 Token，生成依赖上下文和概率。

## 术语表

| 中文 | 英文 | Day 1 应掌握的解释 |
|---|---|---|
| 大语言模型 | Large Language Model, LLM | 根据上下文对后续 Token 建模并生成内容的模型 |
| 词元 | Token | Tokenizer 切分得到的离散处理单位 |
| 分词器 | Tokenizer | 在文本与 Token/Token ID 之间转换的组件 |
| 上下文窗口 | Context Window | 单次推理可处理的 Token 总范围 |
| 提示/输入 | Prompt/Input | 提供给模型、影响生成结果的上下文 |
| 推理 | Inference | 用训练完成的模型对输入计算输出的过程 |
| 生成 | Generation | 逐步产生输出 Token 的过程 |
| 解码 | Decoding | 从概率分布选择输出 Token 的策略过程 |
| 应用程序接口 | Application Programming Interface, API | 程序访问远程能力的约定 |
| 软件开发工具包 | Software Development Kit, SDK | 将底层 API 封装成语言友好接口的库 |
| 模拟对象 | Mock | 用确定性实现替代外部依赖，便于学习和测试 |
| 智能体 | Agent | 围绕目标进行决策、行动并利用反馈继续处理的系统 |

## 必要原理，不做过度数学化

模型生成第 `t` 个 Token 时会参考之前的 Token：

```text
P(x_t | x_1, x_2, ..., x_(t-1))
```

它表达的是“已经看到前面内容时，下一个 Token 的可能性”。模型会反复执行这个步骤，直到满足停止条件或达到输出上限。

需要保留的三个结论：

1. 同一输入不保证永远得到逐字相同的输出。
2. 流畅输出不自动等于正确事实。
3. 输入上下文的内容和组织方式会影响结果。

## API 调用不是魔法

`client.responses.create()` 背后仍是网络请求。它至少涉及：

- 客户端配置；
- HTTPS 连接；
- API Key 鉴权；
- 请求参数序列化；
- 服务端模型推理；
- 响应反序列化；
- 异常与限流。

SDK 降低了调用难度，但没有消除这些环节。因此“导入成功”只能证明包装库存在，不能证明 Key、网络、模型权限和额度都有效。

## Mock 的正确定位

Mock 适合验证：

- 函数输入输出契约；
- 空输入和异常分支；
- 上层程序控制流；
- 不依赖网络的自动化测试。

Mock 不能验证：

- 真实模型对自然语言的理解质量；
- Token 消耗和真实延迟；
- 账户模型权限；
- 真实 API 的全部响应形态。
